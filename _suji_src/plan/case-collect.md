# 실사업 사례 수집 기능 — 준비안 (2026-11-21, 아직 미적용)

목표: 실제 사업수지표 사례 1,000건을 모아 요율·단가를 보정하고, 그 전까지는 정확도 수치를 공개하지 않는다.
상태: 설계·DB 스키마·약관 초안만 준비. 앱 화면·DB 적용은 법률 검토와 사전 공지 뒤에 한다.

## 1. 무엇을 받나 (최소 수집)
받는 것 (숫자·구분만)
- 상품, 시도·시군구, 용도지역, 사업 연도
- 대지면적(평), 연면적(평), 세대·호실 수
- 실제 토지비·공사비·총사업비·총매출(억), 금융 구조(PF형·분양불·차입형)
- 같은 조건의 SuziQ 추정치(앱이 자동으로 채움), 앱 버전, 동의 문구 버전

받지 않는 것
- 지번·주소, 사업명, 회사명, 담당자, 수지표 파일 원본
  - 지번은 토지 소유자를 특정할 수 있어 개인정보가 될 수 있음 → 시군구까지만
- 이름·연락처 (보상을 주면 그때만 별도 동의로)

## 2. 화면 흐름
1. 4단계 결과 화면 아래: "실제 수지표가 있나요? 내 사업과 비교해 보세요"
2. 지금 입력값이 미리 채워진 폼 → 실제 총액 4개(토지비·공사비·총사업비·매출)만 추가로 입력
3. 체크박스 2개 (둘 다 필수, 기본 해제)
   - [ ] 이 수치를 공유할 권한이 있습니다(회사 비밀유지 의무에 어긋나지 않음)
   - [ ] 지번·사업명 없이 통계 보정에 쓰는 데 동의합니다 (개인정보처리방침 4-1)
4. 보내면 바로 "SuziQ 추정 vs 실제" 항목별 차이를 보여 줌 → 사용자에게도 이득
5. 제보 1건 = 프로 1개월 무료(선택, 12/21 유료 시작 뒤) — 보상하면 연락처 별도 동의 필요

## 3. 품질 관리
- 자동 걸러내기: 총사업비/매출 0.5~1.3 밖, 공사비 평당 200만~3,000만 밖 → status `review`
- 중복: 같은 시군구 + 연면적 ±2% + 연도 → `dup` 표시
- 기기당 하루 5건 제한
- 보정에는 운영자가 `ok`로 확인한 건만 사용
- 정확도 공개 기준: `ok` 1,000건 이상, 보정에 안 쓴 20%로 따로 검증한 값만

## 4. DB (Supabase `guwnuaeainixryxdxids`)
`../supabase/migrations/suji_cases.sql` — 아직 적용하지 않음.
- 표 `suji_cases`: 익명 쓰기만 RPC로 허용, 읽기는 막음(RLS)
- RPC `suji_case_submit(jsonb)`: 형식·범위 검사, 기기당 하루 5건, status 자동 지정

## 5. 문서 변경 (초안)
### 개인정보처리방침 — 새 항목 "4-1. 실사업 사례 제보(선택)"
> 이용자가 직접 제보하기를 고르고 동의한 경우에만, 상품·시군구·용도지역·사업 연도·면적·세대수·실제 토지비·공사비·총사업비·매출·금융 구조와 같은 조건의 SuziQ 추정치를 받습니다. 지번·주소·사업명·회사명·이름은 받지 않습니다. 목적: 계산 요율·단가 보정과 정확도 검증. 보유: 서비스 종료 시까지(제보자가 기기번호로 삭제를 요청하면 지체 없이 삭제). 익명 기기번호는 하루 제보 수 제한에만 씁니다.

### 이용약관 — 새 조항 "제보한 사례의 이용"
> 이용자는 제보하는 수치를 공유할 정당한 권한이 있음을 보증합니다. 운영자는 제보 수치를 개별 사업이 드러나지 않는 통계 형태로만 계산 보정·검증에 쓰며, 원 수치를 외부에 공개하거나 제3자에게 제공하지 않습니다.

### 시행 절차
1. 초안 법률 검토 (특히 비밀유지 보증 조항, 개인정보 해당 여부)
2. 방침·약관 개정 공지: 시행 7일 전 (새 선택 항목 추가라 불리한 변경은 아님 — 검토 때 확인)
3. 마이그레이션 적용 → 앱에 제보 폼 켜기 (`CASE_COLLECT = true`)
